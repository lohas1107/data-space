架構與規格邊界

圖面可水平捲動；亦可開啟 2 倍解析度 PNG。所有步驟直接標在連線上。

Provider 與 Consumer 是此次資料交換的角色；雙方均具有 Security Token Service、Credential Service、Decentralized Identifier Service、Control Plane 與 Data Plane。Holder／Verifier 依互動決定。方框表示邏輯服務，分組不構成獨立部署要求。

Registration System 處理加入治理，Issuer Service 位於 Trust Services 內。管理 Client 的操作介面、STS 內部介面與資料來源／應用整合未由圖列協定規範，使用虛線。DID Resolution 為依 DID method 實現的邏輯解析；不指定固定 HTTP 端點。Catalogue、Vocabulary、Observability 與 Value Creation 保留為選用服務，沒有強制串入編號流程。

本圖採 Consumer 直接查詢 Provider 的受保護目錄，DCP 驗證身分、VP／VC 後由 Provider 依政策回應。CIP 的受理回應不等於完成簽發；VC 非同步交付至 Credential Service。DCP 也可用於後續 DSP 互動，並非每次都需重新簽發 VC。詳細說明見DCP 身分、憑證與流程說明。

呈現有限資料傳輸的成功流程。兩種模式皆由 Consumer 提出 DSP 傳輸請求；Pull 主動請求資料，Push 主動傳送資料。Push 在 Provider 資料流啟動後即可傳送，可能先於 Consumer 收到 Started Notification。Prepared／Started 可同步回應或非同步回呼；例行 ACK、重試、錯誤分支及內部驗證不展開。

  • Data Plane Signaling 1.0-RC4（候選版）：Control Plane 與 Data Plane 的資料流控制。
  • DID Core：DID 與文件解析；DSSC Blueprint：服務分類參考。
